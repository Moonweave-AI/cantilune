# ADR-0011：评估架构——持久化、隔离与预算边界

| 字段       | 值                                                                                                                       |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| 状态       | **Accepted**（M2–M3 工程范围）                                                                                           |
| 日期       | 2026-08-12                                                                                                               |
| 决策负责人 | Joker-of-Gotham (DRI)                                                                                                    |
| 评审人     | Joker-of-Gotham（DRI 临时架构）                                                                                          |
| 相关       | RFC-0003、ADR-0009、ADR-0010、`@cantilune/evaluation`、`@cantilune/conformance`、`@cantilune/core`、`@cantilune/runtime` |

## 背景

Cantilune 需要为 `@cantilune/evaluation` 建立显式架构，然后该模块才能作为可信的 agent 行为、基准声称及一致性相关证据的测试平台。评估层必须持久化运行 artifact 与审计轨迹，隔离不可信执行（包括 LLM 评判器），对外部调用施加预算限制，并产出按 RFC-0003 绑定到可验证证据的指标行。

缺少这些边界，评估运行面临静默数据丢失、经评判器的凭据泄露、无上限的提供商支出、含糊的重试语义，以及无法按策略版本重放或审计的已发布指标等风险。

## 决策

### 1. 四种存储类型

| 存储                    | 语义                    | 承载内容                                                    |
| ----------------------- | ----------------------- | ----------------------------------------------------------- |
| **不可变 CAS**          | 内容寻址；一次写入      | 数据集固定件、被测 subject artifact、oracle 输出、证据 blob |
| **事务性运行存储**      | 每次运行/套件 ACID      | 运行状态、尝试记录、中间评分输入                            |
| **追加式声明/审计账本** | 有序、防篡改            | 声明决策、预算事件、外部调用尝试、审计事件                  |
| **受限加密存储**        | 按密钥划分；与 CAS 分离 | 提供商凭据、含 PII 的评判器提示（如有）                     |

适配器**不得**将这些合并为单一通用 blob 存储。跨存储引用仅使用摘要。

### 2. 执行隔离

评估执行运行于**默认拒绝沙箱**中：

- 被测运行**可以**在声明的足迹下调用已配置的适配器（runtime、observability）。
- **LLM 评判器**进程**不得**拥有任何工具、任何网络、任何密钥——输入与输出为绑定到尝试记录的不透明文本。
- 沙箱策略在执行端口处强制实施，而非留给调用者自律。

### 3. 预算控制

外部调用（LLM 提供商、远程 oracle）遵循**先预留后调用、后对账**：

1. 发起调用前从运行预算中预留估计的成本/单位。
2. 收到提供商响应后对账实际用量（退还或补收差额）。
3. 预算耗尽时**失败关闭**——不得静默超额或出现负余额。

### 4. 外部调用非精确一次

提供商 API 不保证精确一次投递。每次外部调用**必须**记录：

- **请求尝试**（尝试 id、载荷摘要、预留 id）
- **提供商回执**（响应摘要、计费单位、提供商关联 id）
- **可能重复**标志，当幂等性无法证明时

重试创建新的尝试记录；**不得**覆盖先前失败或含糊的记录。

### 5. 运行期间证书撤销

若运行所依赖的信任根或证书在运行期间被**撤销**（依 ADR-0009 撤销检查点），引擎**必须**检测该变更并**失败关闭**——不得部分发布绑定到过期信任状态的指标。

### 6. 已发布指标绑定（RFC-0003）

每个已发布指标行**必须**绑定：

| 字段             | 来源                                 |
| ---------------- | ------------------------------------ |
| Artifact subject | 被评估 subject 摘要 + 类型           |
| 验证器构建       | 引擎/oracle 构建摘要                 |
| 策略版本         | 评估策略摘要                         |
| 证据根摘要       | 基于尝试 + oracle 证据链的 Merkle/根 |

未具完整绑定的行**不得**作为权威分数导出。

### 7. 理论 oracle 前提纪律

理论 oracle（形式化/Lean 相关检查）在定理前提不满足时**必须**返回 **`premiseMissing`**——**绝不**在前提不完整或未满足时通过。通过需要显式的前提满足记录于证据中。

### 8. 重试语义

一次重试**总是**创建一个**新尝试**，附带新的尝试 id。失败、含糊或被取代的尝试保留在账本中供审计。终态失败记录不得就地覆盖。

## 信任边界

```
Dataset/subject CAS ──► run planner ──► sandbox executor
                              │                │
                              ▼                ▼
                    budget ledger ◄── external call port
                              │
                              ▼
              scoring + metric binding (subject · verifier · policy · evidence root)
                              │
                              ▼
                    published report (immutable export)
```

| 边界 | 规则                                              |
| ---- | ------------------------------------------------- |
| 入口 | Subject 与数据集经 CAS 摘要解析；无基于路径的信任 |
| 执行 | 默认拒绝；强制评判器隔离                          |
| 出口 | 外部调用仅经带预算的端口，并记录尝试/回执         |
| 发布 | 指标行需四向绑定；导出时重新检查撤销              |

## 结果

### 正面

- 评估 artifact 可审计、可重放，并具有对齐 RFC-0003 的显式证据链。
- LLM 评判器隔离关闭了基准测试平台中常见的凭据外泄路径。
- 预留/对账预算控制以确定性失败关闭行为防止失控的提供商支出。
- 重试与重复语义显式——不静默丢失失败尝试。

### 负面

- 四种存储类型相比单一持久化后端增加了适配器表面积。
- 先预留后调用增加延迟，且对某些提供商需要准确成本估计。
- 运行期间撤销失败关闭可能在信任轮换时中止长时间套件——运维者须规划检查点边界。
- 理论 `premiseMissing` 严格性可能在数据集完整声明前提之前降低标题通过率。
