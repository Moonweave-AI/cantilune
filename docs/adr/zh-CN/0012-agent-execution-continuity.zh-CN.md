## 背景

一次现场运行暴露了四个相互强化的失败：

1. 一个文件支撑的世界可在不同的运行时 epoch 或一个新生成的本地 principal 下恢复，导致协调面无法准入操作；
2. 每次 `CantilunOS.run()` 调用都创建一个新的 LLM 转录，即使 CLI 显示的是一个连续的对话；
3. `write_content` 产生一个有效的 SHA-256 `ContentRef`，而 `introduce_artifact` 静默地创建了一个不同的 `content://<artifactId>` 引用，没有任何已配置的内容存储能解析它；
4. `done` 将模型的摘要视为成功，即使内容读取或协调操作有未解决的失败。

这些是边界违规而非提示质量问题。`CollaborationSnapshot` 是共享协调世界，Agent 的消息历史是私有执行状态，内容存储是 blob 存在的权威，而模型摘要是声称而非证据。

保留的现场转录也反驳了后来助手的解释。在 `introduce_artifact("financial-ecosystem-overview")` 之后写入的确切 1,097 字节 UTF-8 Markdown 正文重计算为 `sha256:dd24a81fe31e4a810ec178acd7597ac3fa994f14aa10749e9c27ef13273cb8ed`，与 `write_content` 结果精确匹配。后来那次运行将 ArtifactId `financial-ecosystem-overview` 而非那个 `ContentRef` 传递给 `read_content` 两次。因此声称正文从未被写入是错误的。旧的运行时/内容包已不存在，故该证据恢复了源字节，但本身并不修复历史 artifact 映射。

## 决策

### 1. 私有会话连续性

- 一个已启动的 Agent 跨用户提交拥有一个私有的、可复用的 `LlmMessage` 历史。
- 私有历史**不得**被写入 `CollaborationSnapshot`、`CoordinationChange` 或共享审计尾。
- Boot 暴露它实际使用的 `AgentLoopHistory` 的一个分离的、严格校验过的快照。文件支撑的 CLI 将该确切历史与可见会话存储于一个带版本的修订 CAS 封套中；**不得**从仅显示的系统行、错误或工具卡片重建已执行的工具证据。
- 在每个完整的 LLM 响应/工具结果组之后，Boot 同步私有历史并等待宿主检查点后再进入下一轮 LLM。检查点失败以类型化错误终止运行并毒化该 OS 实例：后续运行在内容、观测或 LLM 工作之前即失败，直到 OS 从最后验证的持久历史重建。该边界在优雅进程重启之间保持确切的 `ContentRef` 结果与待处理观测回执。
- 若运行在接收中的多工具组中途终止，每个未执行的同级获得一个显式 `SKIPPED: NOT EXECUTED` 结果。完整组被检查点记录，跳过的调用计为失败请求而不假装副作用已发生，终态结果保留确切的聚合计数。
- 一个遗留 v2 CLI 封套仅迁移非空的用户/助手文本。它不将遗留 UI 工具卡片提升为可信历史。
- 一个持久化转录绑定到其持久性模式、规范存储路径与 principal。遗留或不匹配的会话文件保持未绑定状态，**不得**用于初始化一个不同的世界。
- 内存模式世界是进程局部的，因此从不恢复或持久化跨进程转录，即使 CLI principal 字符串恰好稳定。
- 为提供商、模型或端点变更而替换内存模式运行时/内容世界，在等待关闭后清除私有与可见历史。文件模式仅在持久世界世代保持不变时才可保留确切历史。
- 确切的检查点历史独立于有界的提供商上下文。上下文压缩保留当前目标与完整的助手-工具/结果组，至多发出一个标记，并遵守已配置的消息预算。若最新完整组无法放入下一个提供商请求，Boot 将其检查点记录并失败关闭，而非隐藏其证据。

### 2. 可达的 artifact 内容

- 每个正常的 `WorkArtifact.contentRef` 在 artifact 提交时**必须**标识已配置内容存储中存在的内容。
- 公共运行时提交边界——不仅是 syscall——强制执行此不变式。任何创建 artifact 或更改 artifact `contentRef` 的处理器，在所引用字节不可用时**必须**被拒绝。
- 运行时使用同步 `ContentRefAuthority.isAvailable(ContentRef)` 端口进行此最终检查。缺失权威、否定回答或权威异常以 `content_ref_unavailable` 失败关闭；异步 `ContentStore.exists()` 不是提交证据。
- 同样的字面真检查在观测摄取发布新审计尾头之前运行，故直接运行时调用者也不能持久化一个不可达的 `ObservationEntry.payloadRef`。
- `bootMemoryOS`、`bootFileOS` 与 CLI 运行时构造**必须**将同一 `ContentStore` 实例注入 syscall 与运行时权威端口。直接构造 `CoordinationRuntime` 的低层调用者必须在提交任何承载内容的 artifact 之前提供一个权威实现。
- 内容输入是显式的 `CoordinationIntent.inputContentRefs`；它们既非授权也非外部证据，因此不被编码为 `EvidenceRef`。
- `introduce_artifact` 需要一个真实的内容输入。它**不得**合成 `content://<artifactId>`。
- 感知暴露确切的 `contentRef` 并使用公共工具名 `read_content`，使其给 Agent 的指令可执行。
- 这是一条前向完整性规则，而非重建算法。一个先前持久化的 `content://<artifactId>` 指针在缺少原始字节或其他权威映射时无法修复；迁移必须失败关闭或使用经显式审查的源证据。
- 同步可用性检查假定已配置的内容存储在运行时提交期间是可信且追加式的。它不是跨任意可变文件系统或敌意自定义权威的事务。

### 3. 证据感知完成

- `done` 仍是显式的循环终止请求，但它不是成功的充分证据。
- 循环记录每个工具结果，不仅是协调准入结果。
- 在当前运行内，一个失败的工具/目标保持未解决，直到一个语义等价的恢复成功。一个带未解决失败的 `done` 请求返回一个失败的 `RunResult`，其 `tool_end` 事件也是失败的。新的用户指令开启一个新的普通业务失败账本；先前结果保留在私有历史中供模型检查。仅未解决的外部副作用观测回执跨运行恢复，因为其安全歧义仍然存活。
- 已知执行失败的缺失不是领域成功谓词。一个要求特定 artifact、批准或共享世界状态的任务**必须**分别验证该后置条件；`done.summary` 仍是声称，无法证明一个被省略的操作已发生。
- 来自感知、动作发现或工具执行的异常被转换为结构化终态错误与关闭的生命周期事件；它们不以无类型 rejected promise 逃逸。
- 外部工具调用携带其原始 LLM 工具调用 id。执行后，syscall 存储输出与一个内容寻址恢复回执——绑定 principal、工具名、调用 id、规范参数摘要与输出 ref——在尝试审计观测之前。
- 若仅审计观测失败，恢复**必须**验证该确切回执并仅重试 `runtime.observe`；**不得**再次调用外部执行器。不同的调用 id、输出 ref、回执 ref、principal 或参数摘要无法清除原始失败。
- 通用的 `cantiluneRecoveryOf` 替换限于 `read_content` 与 `write_content`。外部工具使用已验证的观测回执，协调操作忽略该字段；因此对目标 B 的成功操作无法擦除对 A 的拒绝操作。
- 调用者中止与本地 LLM 截止独立于适配器协作强制执行。迟到的响应或流增量无法在竞争已结算后分派工具。
- 与重放相关的小操作数是显式的 `CoordinationIntent.scalarInputs`；它们与实体绑定、内容引用与证据分离。
- `emit_heartbeat` 需要非负安全整数 `turnCount` 与非空 `lastAction`。缺失或格式错误的值失败关闭，而非默认为 `0` / `unknown`。
- 运行时在提交时读取一次时钟，将该值持久化为 `ReplayRecipe.emittedAt`，并要求同步的、由解析器支撑的且文件重启的重放重用它。

### 4. 持久 CLI 身份与状态

- CLI 生产运行默认使用文件支撑的运行时与内容存储。内存模式是显式的（`--ephemeral`），不作为可恢复呈现。
- 本地 CLI principal id 跨重启稳定，并在 LLM 轮开始前对恢复的世界进行校验。新身份不被静默自注册。
- 静态模式准入需要显式的模式/epoch 绑定。它**不得**用从持久头读取的任意 epoch 重新标记调用者的已编译模式。epoch 名称或命名空间不是模式证据：每个遗留别名必须在 Owner 审查的 `compatibleEpochIds` 迁移配置中逐个列出。无显式列表时，每个外部 epoch 失败关闭并需要一个受治理的解析器或迁移。动态 epoch 激活仍受 ADR-0006 治理，且必须保持原子头/模式持有者转换。

### 5. 不可变权威边界

- `CollaborationSnapshot` 深度分离并冻结每个节点与嵌套值。它暴露只读集合而无变更接口，而非依赖 `Object.freeze(native Map)`。
- `MemoryCollaborationStore` 对构造、put、put-if-absent、CAS、get 与 list 边界重新快照，使被拒绝的处理器或调用者变更无法更改权威头。
- `MemoryChangeLog` 与 `RecipeSidecar` 同样对每个入口快照并在每次查询返回新的冻结副本，使调用者无法在准入后重写已提交的变更链或心跳重放操作数。
- 运行时模式上下文与 epoch 绑定被分离；规范模式内容摘要在使用前重计算。控制面模式与策略修订同样被分离并在权威边界处进行完整性检查。
- 这些规则关闭了进程内别名与内容替换漂移。它们不将一系列持久头、持有者与日志写入变为一个跨进程事务。
- 文件支撑的排除通过同目录原子硬链接发布一个完整的 fsync'd 拥有者令牌，并仅释放一个确切的已拥有令牌。失主记录失败关闭；运维者必须证明静默并使用恢复 runbook，而非自动删除过时 PID。

### 6. 根系统审计发现的发布门禁

> **部分被取代（2026-08-15）。** 下面两条 `ClusterSupervisor` 条件写于尚无可信 feed 之时，其前置
> 条件此后已满足：ADR-0015 提供了已提交变更流、`activate_participant`、规范 Manifest 绑定、持久
> 完成与活性策略；ADR-0019 提供了 CLI 启动面与派发调度器。CLI 集群与 swarm 视图因此不再是只读。
> 尚未满足的是权限审查 —— 即「后果」一节所述的独立 QA-L5 架构 + 安全签署 —— 所以门禁是收窄而非
> 解除。原文作为如实记录予以保留。

- `ClusterSupervisor` 仍为实验性，在 RFC/ADR 定义可信的已提交变更流、显式参与者激活、规范 Manifest 绑定、持久完成语义与权限审查之前，**不得**连接到 CLI 生产路径。
- CLI 集群视图是只读投影。它们**必须**声明已注册参与者不会自动启动。
- 心跳操作数与时间戳保真度现为确定性的。这不提供解除 swarm 门禁所需的可信提交流、参与者激活、Manifest 权威、活性策略或持久共享世界完成。
- 跨进程 epoch 转换恢复仍为 Stop-Ship：运行时回执日志当前为进程内存，无法在持久头 CAS 之后关闭崩溃窗口。
- 外部工具精确一次执行仍为 Stop-Ship。仅观测恢复仅在输出与回执均持久后才安全。外部副作用之后但那些写入之前的崩溃或存储失败没有权威调用结果。解除该门禁需要持久预调用日志加上执行器幂等键/状态契约。
- `AbortSignal` 与 `maxTimeMs` 约束 LLM 等待并阻止后续分派，但无法安全地竞争一个已在运行的外部/内容/运行时操作：提前返回可能留下一个未观测的迟到副作用。故可取消执行器契约加幂等结果查询是同一 Stop-Ship 门禁的一部分；`maxTimeMs` 对那些在途操作不是硬墙上时钟上限。
- CLI 仅在一个完整的响应/工具组检查点恢复确切私有历史。同一 LLM 响应中两个工具之间的硬崩溃不是完整检查点，不在持久性声称之内。按工具的崩溃恢复需要一个单独的持久执行日志。
- 通过 mock/手动信号的集群测试或控制面恢复测试**不得**被引用为生产 swarm 执行或跨进程 epoch 原子性已完成的证据。

## 结果

### 正面

- 后续问题可使用实际的先前对话，而不会将私有 Agent 历史泄露到共享世界。
- artifact id 与内容引用不再能漂移为两个不相关的对象。
- CLI 成功输出与 `RunResult.ok` 反映未解决的执行失败，而非模型置信度。
- 文件恢复保留单一 principal、世界与内容命名空间。

### 负面

- `CoordinationIntent` 与 syscall 动作元数据获得一个附加的内容输入契约。
- 创建承载内容 artifact 的直接运行时集成必须接合同步 `ContentRefAuthority`；遗漏现在会拒绝而非持久化悬空引用。
- CLI 会话现在创建持久本地状态，除非显式选择 ephemeral 模式。
- 对话压缩必须保持工具调用组完整性，因此不能是简单的 last-N 切片。
- 编码了隐藏引用或失败后成功的现有测试必须更改。

### 中性

- 本决策不将 LLM 消息放入 `CollaborationSnapshot`，也不使 UI 转录成为授权来源。
- 它不授权网络化生产部署。Stop-Ship 门禁包括生产 `ClusterSupervisor`、跨进程 epoch 激活与外部工具精确一次执行；无一被暗示为后续工作或被单 Agent 闭包覆盖。

## 考虑过的备选方案

| 备选方案                                    | 处置 | 原因                                                     |
| ------------------------------------------- | ---- | -------------------------------------------------------- |
| 仅修复系统提示                              | 否决 | 模型仍缺少历史与可用的内容地址；措辞无法修复缺失数据     |
| 将所有 LLM 消息存入 `CollaborationSnapshot` | 否决 | 违反 Agent 隐私/隔离并将私有推理变为共享持久状态         |
| 将 `ArtifactId` 视为内容存储键              | 否决 | 破坏内容寻址并允许可变/含糊的正文                        |
| 在提交内等待 `ContentStore.exists()`        | 否决 | 运行时提交是同步的；Promise 不是可用性证据且会分裂原子性 |
| 仅在 syscall 中校验                         | 否决 | 公共运行时调用者可绕过 syscall 并持久化悬空内容指针      |
| 信任 `done.summary` 作为最终结果            | 否决 | 自由文本声称无法证明先前操作成功                         |
| 生成新 principal 并自动注册                 | 否决 | 让一个未鉴权的新身份授予自身世界成员资格                 |

## 迁移与验证

1. 为跨运行历史、真实内容绑定、可恢复工具错误、严格压缩、文件重启身份与直接运行时悬空引用拒绝添加确定性回归。
2. 运行受影响包的单元、集成、契约、系统、lint、格式与类型检查。
3. 保持 CLI swarm 执行标注为不可用，直到真实监管者订阅与参与者生命周期被接线并独立验证。
4. 保持跨进程 epoch 激活阻断，直到其回执/请求日志与头在同一事务中持久，或一个经鉴权的恢复协议被批准。
5. 保持外部变更工具阻断精确一次声称，直到预调用日志与执行器幂等/结果查询契约被批准并经崩溃测试。
