# RFC-0004：评估线束——可证伪主张、配对实验与证据发布

| 字段                | 值                                                                                                                                                |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 状态                | **FCP**（2026-08-16 开启；评论期至 2026-08-30；尚未 Accepted）                                                                                    |
| 类型                | 架构 / 治理                                                                                                                                       |
| 风险                | 用于公开优越性主张或产品终止门禁时为 S3；起草范围为 S2                                                                                            |
| 主导者 / 决策负责人 | Joker-of-Gotham（DRI）                                                                                                                            |
| 必需评审人          | AI Eval + Statistics + Security + QA-L5 —— **Joker-of-Gotham**（Owner；COI 已披露，2026-08-16；见 `docs/governance/fcp-entry-2026-08-16.md`）     |
| 创建日期            | 2026-08-12                                                                                                                                        |
| 相关                | RFC-0001 §8, RFC-0003 §7, ADR-0011（伴随文档）, `@cantilune/evaluation`, `@cantilune/conformance`, `formal/proof-obligations.json`                |

> **治理说明：** 本 RFC 是**评估线束**的权威真相来源——使 RFC-0001 优越性主张可证伪的体验主张验证与证据发布系统。聊天讨论不具备权威性。本 RFC 不声称任何基准结果存在、独立评审已签署或公开主张已获授权。

> **命名决议（由本 RFC 冻结）：** 评估主张使用**命名空间化编码** `evaluation.c1`–`evaluation.c5`。产品一致性证书仍为 **C0–C9**。两个命名空间在代码、文档或已发布报告中不得混淆。

---

## 1. 概要

`@cantilune/evaluation` 是**体验主张验证与证据发布系统**。它前瞻性预注册并冻结评估协议，在显式合规性与溯源规则下绑定被试与基线主体，执行配对基准运行，通过声明的评判协议对指标评分，以预注册的统计分析聚合结果，将 Lean 理论预言机集成为有前提定义（而非基准结果），并发布密封的 `ClaimDecision` 值及其完整证据链。

线束**判定**每条 `evaluation.c*` 主张是被支持、不被支持还是不确定——绝不是一个布尔值。它**不**验证产品合规性（那是 `@cantilune/conformance`），也**不**重新证明 Lean 定理。

**当前实现状态：** E1–E8 已在 `@cantilune/evaluation` **工程落地**（覆盖率 ≥90/88）。在协议冻结且独立评审达到法定人数之前，**不是** Acceptance，也**不是**公开基准权威。ADR-0011 已 Accepted。E7 分析层不发出 `supported`。

## 2. 动机

### 2.1 问题

RFC-0001 §8 断言了五条相对被命名基线的可证伪优越性主张。若没有形式化评估框架，三种失败模式反复出现：

| 失败模式        | 症状                          | 根因                      |
| --------------- | ----------------------------- | ------------------------- |
| 事后基准设计    | 看到结果后才选指标            | 没有预注册、冻结的协议    |
| 合规性/评估混淆 | "包已发布"被视为"优于 Cursor" | C9 证书链被坍缩为基准归因 |
| 理论/基准混淆   | Lean 证明状态被引用为基准通过 | 核心定理被当作经验结果    |

RFC-0003 §7 的交接确立了合规性验证证据正确性；评估对照基线度量体验。本 RFC 将**评估侧**操作化。

### 2.2 受益人 / 为何现在 / 不做的代价

- **受益人：** 需要可辩护优越性主张的产品所有者；需要预注册协议的独立评审人；需要依 RFC-0001 §8 的终止/重定范围触发器的治理。
- **为何现在：** `@cantilune/conformance`（RFC-0003）可发射密封 C9 证书；`@cantilune/evaluation` 原型已存在。若没有 RFC-0004，交接契约缺少治理文档，C4/C5 命名在各 RFC 间仍存歧义。
- **不做的代价：** 伪造或不可复现的基准主张；参考→产品升级为营销；项目终止标准（RFC-0001 §8）沦为不可执行的修辞。

## 3. 目标

1. 冻结**五条评估主张**（`evaluation.c1`–`evaluation.c5`），配以显式基线、指标与判定规则。
2. 定义**主张生命周期**、**协议冻结/修订**语义与**证据发布**契约。
3. 规定主张、协议、套件、被试、运行、评分、分析与判定的**领域模型**。
4. 将**理论预言机**集成为有前提 Lean 定义——`premiseMissing ≠ pass`。
5. 强制要求**预注册统计分析**，含置信区间、效应量与多重比较调整。
6. 将**被试主体**绑定到密封 C9 证书，将**基线主体**绑定到固定版本/提交/配置。
7. 记录分离评估与合规性、核心的**依赖规则**。
8. 修订**RFC-0003 §7**以解决 C4 定义冲突并补充 C5。

## 4. 非目标

- 验证产品合规性或修改 C0–C9 证书链（RFC-0003 范围）。
- 重新证明 Lean 定理或从 TypeScript 更新 `formal/proof-obligations.json` 状态。
- 持有私有签名密钥、运行时提交权限或控制面激活。
- 自动批准人工评审或绕过预算/安全停止规则。
- 定义终端用户产品 UI 或营销文案。
- 将 Vitest 通过或非空指标字段视为主张支持。

## 5. 评估主张（evaluation.c1–evaluation.c5）

所有主张编码均为**命名空间化**（`evaluation.cN`）。在评估上下文中不得简写为裸 `C1`–`C5`，以免与合规性 C0–C9 冲突。

| 编码            | 主张              | 基线族        | 主要度量意图（精确指标在冻结协议中）                                                    |
| --------------- | ----------------- | ------------- | --------------------------------------------------------------------------------------- |
| `evaluation.c1` | 表达力            | Cursor        | CantiluneGraph 可表示而 Cursor 固化形态不扭曲即无法表示的工作流的存在性与分类           |
| `evaluation.c2` | 可控性 / 可预知性 | Codex         | 基准套件上的经认证有限 epoch 步数排名与显式资源上界；固定策略下的确定性推进             |
| `evaluation.c3` | 控制面精简度      | Claude Code   | 结构化决策事件与模型决策事件之比；配对任务上人工评分的约束开销                          |
| `evaluation.c4` | 工程精简度        | OpenClaw 系列 | 功能面与核心代码复杂度之比；核心圈复杂度 vs 可比功能集（**保留 RFC-0001 §8 定义**）     |
| `evaluation.c5` | 可观测性即结构    | 临时遥测基线  | trace–执行等价：重放保真度、跨 DAG/Petri/π/态射视角的投影一致性、审计完整性 vs 插桩基线 |

**C4/C5 决议（冻结）：** RFC-0001 §8 的 C4（工程精简度 vs OpenClaw）**保留不变**。可观测性即结构——此前在 RFC-0003 §7 中被误标为 C4——成为 **`evaluation.c5`**，反映 RFC-0001 §6.3 的结构可观测性论点为一条可独立度量的主张。

每条主张必须声明：陈述、零假设、目标总体、被试主体策略、基线族、主要/次要/护栏指标、成功/失败/不确定规则、样本计划、不确定度方法、多重比较策略、停止规则、重定范围/终止规则、所有者及所需评审人角色。

**治理门槛：** 任何核心主张（`evaluation.c1`–`evaluation.c4`）在协议冻结度量后未达标，是依 RFC-0001 §8 的有效项目终止触发器。`evaluation.c5` 未达标触发可观测性/重定范围评审，而非自动终止。

## 6. 主张生命周期

主张经过一个显式状态机。此图之外的转换被禁止。

```
proposed → protocolFrozen → measured → decided → reviewed → published → superseded | retracted
```

| 状态             | 含义                                                                       |
| ---------------- | -------------------------------------------------------------------------- |
| `proposed`       | 主张已起草；协议尚未冻结                                                   |
| `protocolFrozen` | 父协议已冻结；主张字段与指标已锁定                                         |
| `measured`       | 在冻结协议下至少有一个已完成的运行集已评分并分析                           |
| `decided`        | 聚合分析已应用；结果为 **supported**、**notSupported** 或 **inconclusive** |
| `reviewed`       | 独立评审人法定人数已见证（`ClaimDecision` 完成）                           |
| `published`      | 密封判定与证据根已发布到持久存储                                           |
| `superseded`     | 被更新主张版本取代，带显式 `supersedes` 链接                               |
| `retracted`      | 先前已发布判定被撤回，附有记录原因                                         |

**不变量：** 任何主张未经过 `protocolFrozen`、`measured`、`decided` 与 `reviewed` 不得达到 `published`。冻结后追溯协议编辑须通过**修订**创建新协议版本（见 §7）。

## 7. 评估协议

一个 **EvaluationProtocol** 将一条或多条主张与一个 **BenchmarkSuite**、被试选择规则、采样/随机化/盲法计划、指标与分析计划、缺失数据与离群值策略、停止策略、安全/隐私计划引用、预算策略引用及评审策略引用捆绑在一起。

### 7.1 冻结与修订

| 规则         | 要求                                                                                 |
| ------------ | ------------------------------------------------------------------------------------ |
| 预注册       | 协议必须在任何归因于它的基准运行之前注册并评审                                       |
| 冻结         | `freezeProtocol` 设置 `frozenAt` 并将关联主张转换为 `protocolFrozen`；摘要变为不可变 |
| 冻结后仅修订 | 冻结后的变更必须创建新协议版本，以 `amendmentOf` 指向先前协议                        |
| 运行绑定     | 每个 `EvaluationRun` 必须携带准入时生效的冻结 `planDigest` / 协议摘要                |
| 分析绑定     | 聚合分析必须引用预注册的 `analysisPlan`；未声明分析仅为探索性，不得支持可发布判定    |

## 8. 领域模型概览

评估领域组织为可组合实体。精确字段契约见 ADR-0011 与 `@cantilune/evaluation` 源码；本节陈述角色与关系。

| 实体                     | 角色                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| **EvaluationClaim**      | 一条可证伪断言（`evaluation.cN`），含指标、判定规则与生命周期状态                   |
| **EvaluationProtocol**   | 冻结的捆绑，将主张链接到套件、被试、采样、分析与治理计划                            |
| **BenchmarkSuite**       | 带生命周期的版本化基准用例集合（`draft` → `frozen` → `deprecated`）                 |
| **EvaluationSubject**    | 可辨识联合：**CandidateSubject**（绑定 C9）或 **BaselineSubject**（固定的外部产品） |
| **EvaluationRunPlan**    | 可执行计划：协议引用、主张引用、被试配对、用例选择、预算预留                        |
| **EvaluationRun**        | 一个被试执行一个计划；拥有有序 **RunAttempt** 列表，带工作进程的租约/围栏           |
| **RunAttempt**           | 单个用例执行，含种子、证据引用（trace、观测、准入）、用量与成本记录                 |
| **TheoryOracleEvidence** | Lean 有前提预言机检查：范围、定理符号、前提引用、结果（`premiseMissing` ≠ pass）    |
| **MetricDefinition**     | 已声明指标：方向、聚合、端点角色（primary/secondary/guardrail）、主张绑定           |
| **MetricObservation**    | 每次尝试的评分观测；状态为 `valid` / `invalid` / `missing` / `quarantined`          |
| **JudgeProtocol**        | 评分细则：确定性、schema、人工或 LLM 评判，带盲法与评分者间规则                     |
| **AggregateAnalysis**    | 预注册的统计摘要：估计值、置信区间、效应量、配对结果、缺失审计                      |
| **ClaimDecision**        | 最终判定，含证据根、评审人见证、护栏违规、局限性——绝不布尔值                        |
| **BudgetPolicy**         | 成本/运行/token/时间上限、提供方配额、硬杀与安全状态规则                            |

**证据流：**

```
EvaluationProtocol (frozen)
  → EvaluationRunPlan → EvaluationRun → RunAttempt
      → MetricObservation (+ TheoryOracleEvidence where applicable)
          → AggregateAnalysis → ClaimDecision → published evidence root
```

## 9. 理论预言机集成

Lean 提供**有前提预言机定义**，而非基准结果。

| 规则 | 要求                                                                                                             |
| ---- | ---------------------------------------------------------------------------------------------------------------- |
| 范围 | 预言机对照记录的运行证据检查结构性质（重放唯一性、排名界、投影健全性、终态保持等）                               |
| 前提 | 每个预言机列出 `premiseEvidenceRefs`；缺失前提产生 `premiseMissing`，**绝不** `passed`                           |
| 基线 | `theoryBaselineRef` 与 `proofManifestDigest` 必须固定 `formal/proof-obligations.json` 提交                       |
| 分离 | 预言机通过/失败补充经验指标；它不替代配对基线比较                                                                |
| 符号 | 已知定理符号（如 `replayTargetUnique`、`projectionStepSound`、`internalRankDecrease`）被枚举；临时符号需协议声明 |

**不变量：** `kernel proved ≠ benchmark superior`。理论预言机证据可阻塞主张判定（`blocked` / `invalidated`），但不得单独确立 `supported`。

## 10. 统计要求

所有可发布判定必须满足冻结协议中声明的预注册分析。

| 要求            | 规则                                                                           |
| --------------- | ------------------------------------------------------------------------------ |
| 预注册分析      | 主要估计量、方法与 alpha 在 `protocolFrozen` 之前声明                          |
| 置信 / 可信区间 | 所有主要指标均报告；判定规则引用区间与零假设的关系                             |
| 效应量          | 与 p 值或贝叶斯等价物一起报告；方法在分析记录中命名                            |
| 缺失数据        | 声明处理方式（`exclude`、`impute`、`worstCase`、`fail`）；缺失分析包含在聚合中 |
| 多重比较        | 声明调整方法（如 Bonferroni、Holm）；指定检验族                                |
| 停止规则        | 预注册中期分析与提前停止准则；停止审计包含在聚合中                             |
| 配对设计        | 被试–基线对共享用例、种子策略与盲法（适用时）                                  |
| 负面结果        | 不显著与不确定的结果必须与正面结果以同等证据严格度可发布                       |
| 探索性分析      | 事后分析标注为探索性；不得将 `notSupported` 翻转为 `supported`                 |

## 11. 被试绑定

### 11.1 被试主体

每个被试必须绑定一个**密封 C9 `PackageConformanceCertificate`**（或依 RFC-0003 的等效发布判定）：

- 证书摘要、产物主体、策略引用、撤销检查点与有效性轴在准入前验证
- 过期、撤销或被取代的证书阻止准入
- 已发布指标必须记录：证据根摘要、验证器构建、策略版本连同每一指标行（RFC-0003 交接 §7）

### 11.2 基线主体

每个基线必须绑定**精确版本/提交/配置**：

- 产品名、版本、提交或服务版本、适配器版本/摘要
- 模型、提供方、工具、prompt 与策略配置已固定并摘要密封
- 能力清单与已知限制已记录
- 完整源码固定不可行时要求 `provenanceUnavailable` 标志；此类运行在无评审人例外的情况下不得支持可发布优越性主张

**不变量：** 被试与基线是**结构上不兼容**的主体种类；配对发生在计划层，而非通过合并主体类型。

## 12. 安全与隐私

| 关注点     | 要求                                                              |
| ---------- | ----------------------------------------------------------------- |
| 不可信输入 | 基准用例、模型输出、工具结果与基线产物视为不可信数据              |
| 密钥排除   | 已发布证据根中无密钥；prompt 与 trace 按隐私计划脱敏              |
| 预算硬杀   | `BudgetPolicy.hardKillEnabled` 在突破上限时停止运行并进入安全状态 |
| 提供方隔离 | 工作进程租约带围栏令牌；过期工作进程不能提交结果                  |
| 数据分级   | 数据集携带隐私分级（`public` → `restricted`）；隔离数据阻断评分   |
| LLM 评判   | 评判协议要求盲法、校准集与评分者间统计（适用时）                  |
| 审计追踪   | 只追加的运行与判定账本；篡改指标行使主张判定失效                  |
| 威胁模型   | 详细 STRIDE 映射见 ADR-0011 伴随文档                              |

## 13. 依赖规则

| 包                       | 可依赖                 | 不得依赖                      | 与合规性的关系                 |
| ------------------------ | ---------------------- | ----------------------------- | ------------------------------ |
| `@cantilune/evaluation`  | `@cantilune/core` 类型 | `@cantilune/runtime` 提交路径 | 经端口**只读**读取 C9 密封输出 |
| `@cantilune/conformance` | core、runtime（验证）  | `@cantilune/evaluation`       | **不依赖**评估                 |
| `@cantilune/core`        | —                      | evaluation、conformance       | 评估仅组合核心身份/摘要类型    |

评估领域类型不得复制合规性证书结构；它们通过摘要与端口适配器引用。跨包测试导入必须使用包导出（如 `@cantilune/evaluation`），而非深层 `src/` 路径。

## 15. RFC-0003 修订

RFC-0003 §7 已与 RFC-0001 §8 主张名称对齐（2026-08-15 已应用）。**本 RFC 记录该修订如下：**
