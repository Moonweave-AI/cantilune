# T03 文本创意到可玩原型的跨引擎游戏生成

## 目标合同

一句话创意（默认：「开放世界科幻赛车」）变成可玩原型：规则、关卡、物理、输入循环、性能预算。目标引擎可以是 Unity 或 Unreal 的 **数据与脚本等价物**；本轮不强制本机启动编辑器。

## 世界与约束

- 物理参数是共享世界状态。改车辆物理必须同步关卡碰撞体，否则记为回归。
- 空间与时间耦合：同一 tick 的速度、摩擦、检查点必须能对上。

## Peer 角色

剧情/规则、资产清单、玩法代码、关卡、性能与 debug、数值。至少 3 个 peer。改物理的 peer 必须通知关卡 peer。

## 协作与反馈环

性能 peer 若发现卡空或穿透，必须指出是物理改动还是网格改动，关卡/代码 peer 回收。禁止各写各的 JSON。

## Wave-1 必须交付

1. `artifacts/design.md` — 核心循环、胜负、摄像机。
2. `artifacts/physics.json` — 质量、摩擦、重力、最大速度（数值需自洽）。
3. `artifacts/level.json` — 至少 1 条赛道/区域，碰撞与检查点引用同一物理单位。
4. `artifacts/gameplay/` — 可阅读的玩法脚本（C#/GDScript/TS 任一）含更新循环。
5. `artifacts/regression.md` — 一次「改物理 → 关卡失败 → 对齐参数」记录。

## 禁止

只交概念图文、无可执行循环。不要声称「已在 Unreal 出包」却无产物。
