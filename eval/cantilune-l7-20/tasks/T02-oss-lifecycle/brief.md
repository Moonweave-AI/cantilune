# T02 零基础开源项目全生命周期运营

## 目标合同

从一条公开创意出发，走完「立项 → 实现 → 发布记录 → Issue 分诊 → PR 评审 → 对外说明」的完整运营环。外部不确定性（冲突 PR、拒绝、负面反馈）必须在世界里被处理，而不是写在愿望清单里。

本轮不要求向真实 GitHub/Twitter 发帖（除非网络策略明确允许且你能留下可审计回执）。必须在隔离 git 工作区里把运营对象做实。

## 世界与约束

- 工作区即唯一仓库。并发冲突用分支/会话表达。
- 7×24 是目标合同；Wave-1 用多轮 + 多 peer 模拟「同时到达的 Issue 与 PR」。
- 负面反馈与评审拒绝必须留下记录和后续动作。

## Peer 角色

产品、实现、QA、Issue 分诊、社区说明、对外传播——按需 activate，至少 3 个 peer。任何 running peer 都可以再拉人。

## 协作与反馈环

QA 拒绝合并时，实现 peer 必须改而不是覆盖检查点。社区 peer 不得在 QA 未放行时把「已发布」写入 changelog。

## Wave-1 必须交付

1. `artifacts/repo/` — 可初始化的项目（README、许可证、最小可运行代码）。
2. `artifacts/issues.md` — 至少 3 条 Issue，含一条冲突/拒绝。
3. `artifacts/pr-review.md` — 至少一次评审拒绝 + 一次修订后再评。
4. `artifacts/changelog.md` — 与仓库状态一致，不得早于 QA 放行。
5. `artifacts/comms-log.md` — 对外说明草稿与「未实发」或回执。

## 禁止

用一条自我介绍代替运营。不要叫用户去建仓库。
